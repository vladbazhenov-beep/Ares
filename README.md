# Reelroom

Сервис для просмотра и апрува видео: клиенты и креаторы получают доступ по
email только к своим проектам, оставляют таймкод-комментарии в тредах, а
клиент апрувит ролик или отправляет на доработку.

Это настоящее full-stack приложение на Next.js (App Router) с базой данных
и входом по одноразовому коду на почту — в отличие от прототипа-артефакта,
здесь есть реальная серверная проверка доступа и код на почту отправляется
по-настоящему (через Resend).

## Стек

- **Next.js 14** (App Router, Server Actions, Server Components)
- **PostgreSQL + Prisma** — база данных
- **Resend** — отправка писем с кодом входа (любой другой транзакционный
  email-сервис подключается аналогично в `lib/mailer.js`)
- Сессия — httpOnly cookie с подписанным JWT (`jsonwebtoken`)

## Роли и доступ

- **Админ** — видит все проекты, создаёт проекты, добавляет пользователей и
  назначает им доступ к конкретным проектам, видит колонку «Исполнитель».
- **Клиент** — видит только проекты, к которым админ дал доступ; может
  апрувить ролик или отправить на доработку, когда он в статусе
  «To approve».
- **Креатор** — видит только свои проекты; ставит статус «В работе» и
  «Отправить на апрув».

Доступ выдаётся по email в разделе «Доступы» админ-панели — ничего не
настраивается пользователями самостоятельно.

## Запуск локально

1. Установите зависимости:
   ```bash
   npm install
   ```
2. Скопируйте `.env.example` в `.env` и заполните:
   - `DATABASE_URL` — строка подключения к Postgres (подойдёт бесплатный
     [Neon](https://neon.tech) или [Supabase](https://supabase.com), либо
     локальный Postgres).
   - `SESSION_SECRET` — длинная случайная строка, например:
     ```bash
     openssl rand -base64 32
     ```
   - `RESEND_API_KEY` и `MAIL_FROM` — можно оставить пустыми на этапе
     разработки: код входа будет выводиться в консоль сервера и прямо на
     экране логина с пометкой «Демо-режим».
3. Создайте таблицы в базе:
   ```bash
   npx prisma db push
   ```
4. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
5. Откройте `http://localhost:3000`. **Первый email, которым вы войдёте,
   автоматически станет администратором.**

## Подключение реальной отправки писем

1. Зарегистрируйтесь на [resend.com](https://resend.com), подтвердите домен
   отправителя (или используйте `onboarding@resend.dev` для теста).
2. Создайте API-ключ и укажите его в `RESEND_API_KEY`.
3. Укажите `MAIL_FROM`, например `Reelroom <team@your-domain.com>`.

После этого коды будут приходить на настоящую почту, а не выводиться на
экран.

## Деплой

Проще всего — [Vercel](https://vercel.com) + управляемый Postgres (Neon,
Supabase, Railway):

1. Запушьте проект в свой GitHub-репозиторий.
2. Импортируйте его в Vercel.
3. В настройках проекта на Vercel добавьте переменные окружения из `.env`.
4. После первого деплоя выполните `npx prisma db push` с продакшен
   `DATABASE_URL` (можно через `vercel env pull` локально и разовый запуск
   команды).

## Видео

Приложение не хранит видеофайлы само — при создании ролика указывается
прямая ссылка (`videoUrl`) на файл, например с S3/CloudFront, Cloudflare
Stream, Mux или Bunny Stream. Если ссылку не указать, вместо плеера
показывается заглушка. Настоящую загрузку файлов (drag-and-drop с
прогресс-баром) можно добавить отдельно через presigned-URL в S3-совместимое
хранилище — дайте знать, если это нужно, и я помогу это спроектировать.

## Известные ограничения MVP

- Нет рейт-лимита на запрос кода — для продакшена стоит добавить (например,
  через Upstash Redis) на уровне `requestCode`.
- Нет ролей "только просмотр без комментариев" — сейчас у клиента и креатора
  фиксированный набор прав, но `lib/actions/items.js` и `lib/actions/users.js`
  — правильное место, чтобы расширить логику ролей.
- Загрузка видео — только по ссылке, см. раздел «Видео» выше.
